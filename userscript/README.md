# 正方教务系统 滑块验证码自动通过（油猴脚本 · 纯 HTTP 版）

[zf-jwglxt-slider-captcha.user.js](zf-jwglxt-slider-captcha.user.js)

在正方教务（zfsoft，`/jwglxt`）登录页自动通过滑块验证码。**全程走 HTTP 接口，不模拟鼠标、不移动光标**——不会打断你正在用的鼠标。
识别与轨迹算法移植自本仓库的 `check_code` 包（`matcher.go` / `gen_track.go`），协议部分对应 `protocol/login.go`。

## 安装

1. 浏览器安装 Tampermonkey（油猴）扩展；
2. 打开 Tampermonkey 面板 → 「添加新脚本」，把 `.user.js` 内容整段粘贴进去保存（或直接把文件拖进浏览器）；
3. 打开教务登录页，滑块会自己变成「验证通过」，右下角有状态提示，控制台有日志。之后正常输入账号密码点登录即可。

生效范围：`@match *://*/jwglxt*` 与 `*://*/xtgl/login_slogin.html*`；页面没有 `.captcha_wrapper` 时脚本不做任何事。

## 工作原理（v2：不碰鼠标）

| 步骤 | 做法 |
| --- | --- |
| 1. rtk | 读页面上的 `window.zfdun_captcha_config.rtk`；拿不到就再请求一次 `zfdun_captcha.js` 解析 `rtk:'...'` |
| 2. 取题 | 优先复用页面上正在显示的那组图（界面一致、**一张图都不用再下载**）；失败或重试时 `GET ?type=refresh` 换新题 |
| 3. 取像素 | 页面已显示的题：直接把现成的 `<img>` 画到 canvas 取像素（0 次网络请求）；自己换的题：每张图只下载 1 次，同一份 blob 既用于识别、也用 objectURL 更新页面显示（见下） |
| 4. 缺口定位 | NCC 滑窗匹配出缺口 x（见下） |
| 5. 造轨迹 | 1:1 移植 `gen_track.go` 的「平滑插值 `3t²-2t³` + 正弦抖动」轨迹，24 个点、约 1.36 秒 |
| 6. 提交 | `POST ?type=verify`，`mt=base64(轨迹JSON)`、`extend=base64({appName,userAgent,appVersion})`、`rtk`、`time` |
| 7. 判定 | 返回 `{vs:"verified", status:"success"}` 即通过；服务端已把会话标记为已验证 |

### 图片为什么只下载一次

页面上那两张图（背景图 + 拼图块）浏览器本来就已经下载过一次，v2.0 会用自己的 `fetch` 再下载一遍（自己换题时还要被 `img.src` 触发第三次），
在 DevTools 里表现为同一组图被反复获取。v2.1 改成：

- **复用页面上正在显示的题** → 直接对现成的 `<img>` 做 `drawImage` + `getImageData`，**0 次网络请求**（跨域污染 canvas 时自动回退到 fetch，并且不会白等 2 秒）；
- **自己 `refresh` 换题** → 每张图只下载 1 次，拿到的 blob 一份两用：既解成像素做 NCC，又用 `URL.createObjectURL` 挂到页面上显示，
  所以「同步页面图片」不会再让浏览器重新请求一次；
- 同一 URL 的图片进 blob 缓存（最多 8 张），重试、重入都不会重复取图；
- `#tips` 的 MutationObserver 加了去重（整棵文档都在观察，页面自身重绘也会触发），避免同一段提示把整个流程反复重跑一遍。

### 缺口定位为什么用 NCC 而不是照搬 check_code 的 SAD

- `check_code/matcher.go` 是「拼图块取模板 → 与自带的 10 张干净背景图滑窗取绝对差之和最小 → `+70`」。`+70` 是因为那批背景图是把原始 304px 宽的背景**裁掉左边 70px** 得到的（commit “背景图瘦身”）。
- 浏览器里不必内置那 10 张图：直接抓页面上这张 304×200 的背景图即可，也就没有 `+70`。
- **但不能照搬 SAD**：页面上的背景图叠了一层半透明白蒙版（`si = α·255 + (1-α)·原图`，整图洗白、缺口处额外提亮），绝对差会被带偏 —— 实测 40 组真实样本 **SAD 命中 0/40**。
- 改用对 `a·x+b` 线性变换不变的**归一化互相关（NCC）**：正位置相关系数 ≈0.9999，次高峰 ≤0.78。

### 轨迹为什么要改两处

1. **时间戳**：与 `gen_track.go` 完全一致 —— 从当前时刻往后排（末点落在未来 ~1.36s）。服务端不看这个「未来」，轨迹生成完立刻提交即可，不需要 `sleep` 等它「回到过去」。
2. **首点归零 + 末点对准**：首点位移设为 0（等价于 mousedown 瞬间），末点正好落在缺口位置，于是「末点 − 首点」**正好等于缺口 x**，与真人拖动产生的 mt 完全一致。
   轨迹坐标用滑块在页面上的真实位置；拿不到才退回 `protocol/login.go` 的 `950~1030 / 480`。

## 可调配置（脚本顶部 `CFG`）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `debug` | `true` | 控制台日志 + 右下角状态提示 |
| `maxAttempts` | `2` | 一次自动通过最多尝试几轮（每轮换一组新题） |
| `retryDelay` | `700` | 两次尝试间隔(ms) |
| `cooldownMs` | `1200` | 两次自动通过之间的最小间隔 |
| `minScore` / `minMargin` | `0.95` / `0.1` | NCC 置信度门槛（实测最低 0.9997 / 0.19） |
| `reusePageChallenge` | `true` | 优先复用页面上正在显示的那组图 |
| `syncPageImages` | `true` | 自己换题后把页面图像同步成同一组 |
| `markVerifiedUI` | `true` | 通过后把滑块 UI 改成「验证通过」，并把拼图挪到缺口位置 |
| `autoClickLogin` | `false` | 通过后自动点「登录」（账号密码需已填好） |
| `useDomDragFallback` | `false` | **应急兜底**：HTTP 连续失败时才改用真实鼠标事件拖动。默认关闭，开启后会有鼠标移动 |

## 验证情况

全部针对真实服务端（浙江工业大学正方教务）实测，脚本本体从浏览器之外的环境调用：

**1. 协议：纯 HTTP 提交被服务端接受**
- `?type=verify` 连续 **12/12** 返回 `{vs:"verified", status:"success"}`（两种轨迹风格各 6 次），NCC 相关系数 0.9998~1.0000。

**2. 登录门禁：验证之后服务端确实放行**（用不存在的账号提交，只看 `#tips`）

| | 服务端返回的 `#tips` |
| --- | --- |
| 对照组（不做滑块验证） | `请先滑动图片进行验证！` |
| 实验组（纯 HTTP 完成滑块验证，零鼠标事件） | `用户名或密码不正确，请重新输入！` |

实验组不再被滑块拦住，说明会话的验证状态已经生效。

**3. 识别精度**：脚本本体里的 `buildMask` / `matchByNCC` 跑 40 组真实样本，与 `check_code` 生产路径（干净背景图池 + SAD + 70，用 numpy 独立算出）**逐组完全一致 40/40**，最低相关系数 0.9997、最低峰间隔 0.19，单张约 4ms。

**4. 流程干跑**（[`test/dry-run.mjs`](test/dry-run.mjs)：假 fetch + 假 DOM + 合成图片，跑完整 `solve()`，重点统计图片被下载了几次）：

```
node userscript/test/dry-run.mjs     # 17/17 通过
```

覆盖的点：复用页面上的题 = **0 次图片下载**；自己换题 = 背景图/拼图块**各只下载 1 次**（共 2 次请求），且换题后页面改用同一个 blob 的 objectURL 显示（不再触发第二次下载）；
连着再 solve 一次仍然 0 次请求；页面图跨域、canvas 被污染时回退到 fetch 且不被卡住；`#tips` 反复重绘只触发一次；
轨迹末点落在未来、末点−首点 = 缺口 x（缩放成 152px 显示时 mt 位移仍是图像素 x，服务端比对的是挑战图坐标，不能乘页面缩放）；**全程鼠标事件数 = 0**。

## 注意

- 脚本只处理滑块拼图；如果是图形验证码（`#yzmDiv`）分支，脚本不做任何事。
- 页面 CSP 为 `script-src 'self' 'unsafe-inline'`，`@grant none` 的注入方式可用；若站点日后收紧 CSP，可改用 `@grant unsafeWindow` 等沙箱方式（把 `window` 换成 `unsafeWindow`）。
- 验证状态与会话绑定：若你在通过之后又点了滑块上的「刷新」按钮，脚本会自动对新题重做一次（换题可能会让服务端重新要求验证）。
